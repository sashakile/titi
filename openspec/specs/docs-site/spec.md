## Requirements
### Requirement: Documentation Site

The system SHALL provide a documentation site published to GitHub Pages, generated by DocFX, containing API reference, usage guides, and browsable openspec specifications.

#### Scenario: Local build
- **WHEN** `just docs` is run
- **THEN** DocFX generates the site in `docs/_site/` without errors
- **AND** the site includes API reference from C# XML doc comments in `src/titi/`
- **AND** the site includes hand-written markdown content from `docs/`
- **AND** the site includes openspec specs from `docs/specs/`

#### Scenario: Local preview
- **WHEN** `just docs --serve` is run
- **THEN** DocFX starts a local HTTP server on `localhost:8080`
- **AND** the site is accessible at `http://localhost:8080`

#### Scenario: CI deployment
- **WHEN** a push to `main` includes changes to `docs/`, `openspec/specs/`, or `src/titi/`
- **THEN** the GitHub Actions workflow builds the site
- **AND** uploads the output as a Pages artifact
- **AND** deploys to GitHub Pages
- **AND** the site is accessible at the repository's Pages URL

#### Scenario: No `gh-pages` branch
- **WHEN** the documentation site is deployed
- **THEN** no `gh-pages` branch is created or updated
- **AND** deployment uses artifact-based GitHub Pages (upload + deploy actions)

### Requirement: DocFX Configuration

The system SHALL include a `docs/docfx.json` configuration file that defines the documentation metadata sources, content paths, and build output.

#### Scenario: Metadata source configured
- **WHEN** DocFX metadata is built
- **THEN** it SHALL scan `../src/titi/**/*.cs` for C# XML doc comments

#### Scenario: Content configured
- **WHEN** DocFX content is built
- **THEN** it SHALL include all `.md` files under `docs/`
- **AND** it SHALL include openspec specs copied to `docs/specs/`

#### Scenario: Build output
- **WHEN** DocFX build completes
- **THEN** the output SHALL be written to `docs/_site/`

### Requirement: Navigation Structure

The documentation site SHALL include a top-level navigation (toc.yml) with sections for getting started, CLI reference, architecture, safety model, and openspec specs.

#### Scenario: Navigation available
- **WHEN** a user visits the documentation site
- **THEN** they SHALL see a navigation sidebar with links to:
  - Getting Started
  - CLI Reference
  - Architecture
  - Safety Model
  - Openspec Specs

### Requirement: API Reference

The documentation site SHALL include API reference documentation generated from C# XML doc comments in the source code.

#### Scenario: Public API documented
- **WHEN** DocFX metadata is built
- **THEN** public types, methods, and properties with XML doc comments in `src/titi/` SHALL appear in the API reference section

### Requirement: Openspec Specs Browsable

The documentation site SHALL include the openspec specification files as browsable reference content.

#### Scenario: Specs available
- **WHEN** `just docs` is run
- **THEN** the openspec specs from `openspec/specs/` SHALL be copied to `docs/specs/`
- **AND** they SHALL be included in the DocFX build

### Requirement: CI Workflow

The system SHALL include a GitHub Actions workflow that builds and deploys the documentation site on pushes to `main`.

#### Scenario: Workflow triggers
- **WHEN** a push to `main` modifies files under `docs/`, `openspec/specs/`, or `src/titi/`
- **THEN** the documentation workflow SHALL run

#### Scenario: Workflow steps
- **WHEN** the documentation workflow runs
- **THEN** it SHALL:
  - Check out the repository
  - Restore the DocFX dotnet tool
  - Run `just docs` to build the site
  - Upload the `docs/_site/` directory as a Pages artifact
  - Deploy the artifact to GitHub Pages

#### Scenario: Workflow permissions
- **WHEN** the documentation workflow runs
- **THEN** it SHALL have `contents: read`, `pages: write`, and `id-token: write` permissions

### Requirement: `just docs` Recipe

The project SHALL include a `just docs` recipe that builds the documentation site with a single command.

#### Scenario: Build without serve
- **WHEN** `just docs` is run
- **THEN** it SHALL restore the DocFX tool
- **AND** copy openspec specs to `docs/specs/`
- **AND** run `docfx docs/docfx.json --output _site`

#### Scenario: Build with serve
- **WHEN** `just docs --serve` is run
- **THEN** it SHALL restore the DocFX tool
- **AND** copy openspec specs to `docs/specs/`
- **AND** run `docfx docs/docfx.json --serve`
